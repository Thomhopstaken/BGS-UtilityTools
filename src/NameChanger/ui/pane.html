BGS-UtilityTools - NameChanger

Rename entities and their associated elements

Changes the published API: its clients must be updated.

How does this tool work?

Before you rename
  • Commit your work first. A rename saves many documents at once, and version control is your clean way back.
  • If the entity is used in a message definition, the import and export mappings using it must be mapped again afterwards.
  • Fix errors in documents that use the entity, such as retrieve activities in microflows. If a document can't be checked during planning, the rename stops before anything is changed.
  • Studio Pro is blocked while the rename runs; the progress dialog shows each step. In a large app this can take a few minutes.
What is renamed
  • The entity, and its source document when it is a view entity
  • Microflows, nanoflows, rules, pages and snippets that use the entity and have its name in their name, e.g. ACT_Order_Save
  • Associations of the entity that have its name in their name
  • Workflows with the entity as context, import and export mappings that map the entity, and JSON structures used by those mappings, when they have its name in their name
  • Message definitions, datasets, Java and JavaScript actions, and published REST, OData and web services that use the entity, when they have its name in their name
  • Exposed names in published services that contain the entity name, only when "Also rename exposed names" is ticked. This includes REST operation parameters and their {Param} placeholders in operation paths; other path text, namespaces and versions are kept
  • Page, snippet, dataset, Java action and JavaScript action parameters of the entity's type that have its name in their name
  • Message definitions of the entity inside a collection that have its name in their name; exposed names are kept
  • The workflow parameter and the export mapping parameter, when of the entity's type and named after it
  • The entity name in workflow texts: title, workflow name and description, task names and descriptions, and activity captions

Matching is case-sensitive and replaces every occurrence of the entity name, so ACT_Orders_Get becomes ACT_Purchases_Get. Names of other entities are protected: renaming Order leaves OrderLine alone.

All current mendix naming validations apply

Which microflow variables are renamed

Variables of the entity's type (object or list) that have its name in their name, in microflows, nanoflows and rules, with every expression that uses them:

  • Parameters, loop iterators and the return variable
  • Create object, create list and create variable
  • Retrieve (from database and by association)
  • List operations and cast object
  • Microflow, nanoflow, Java action and JavaScript action calls
  • REST, web service, external action, ML model and import mapping calls
  • Get workflow data
  • Execute database query, import Excel data and connector action calls

Variables from other activities keep their name.

What you need to check yourself
  • Java and JavaScript action code in javasource and javascriptsource is not updated. The run log warns when an action changed.
  • Import and export mappings that use a changed message definition. They no longer match its schema, and updating them in Studio Pro clears them, so they must be mapped again by hand. The run log lists them per message definition.
  • Report widgets that use a renamed dataset are not updated. The run log warns when this applies.
  • Document templates are deprecated and not updated at all: no names, parameters or references. The run log warns when the app has any.
  • Connector actions: references to renamed Java action parameters are not updated.
  • ML model mappings keep their names, which mirror the model file.
  • Consumed REST and OData services and imported web services keep their names, which mirror the external API.
  • Clients of published services whose exposed names were renamed. The run log warns when this applies.
  • Database connections, Excel importer templates, connectors, business event services and change data capture services keep their names; message and exposed names are never renamed.
  • Navigation: menu items, home pages and the login page that point to renamed documents. The run log warns when this applies.

Marketplace modules and System are never changed.

If a rename fails or is cancelled

Nothing is changed until the entity is renamed. If the rename stops before that, the entity keeps its name and the run log lists why.

If it stops or documents fail after the entity was renamed, documents updated so far keep their new names. The run log lists what failed. Fix those documents by hand, or revert through version control.

Known limitations

This tool is built on Mendix's Extensibility API for Studio Pro 11.12. The API is in beta, so behaviour can change between Studio Pro versions.
