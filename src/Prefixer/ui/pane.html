BGS-UtilityTools - Prefixer

Rename or remove a document prefix across your app

1 to 4 capital letters A–Z.
The names keep everything after the prefix, e.g. ACT_Order_Save becomes Order_Save.

How does this tool work?

Before you rename
  • Commit your work first. A prefix rename saves many documents at once, and version control is your clean way back.
  • A prefix is 1 to 4 capital letters before the first underscore: ACT_Order_Save and ACT_Save have prefix ACT; Act_Save and V2_Save have none.
  • A prefix belongs to one document type: ACT_ on microflows and ACT_ on pages are separate entries. Microflows and nanoflows share their prefixes.
  • Studio Pro is blocked while the rename runs; the progress dialog shows each step. In a large app this can take a few minutes.
What is renamed
  • Every document of the chosen type with the prefix, in the app's own modules: e.g. ACT_Order_Save becomes SUB_Order_Save.
  • Matching is case-sensitive: Act_Order_Save is not renamed.
  • Every reference to a renamed document, including constants in expressions (@Module.Constant), enumeration values, images and page and microflow parameters, in domain models, flows, pages, snippets, layouts, page templates, building blocks, menus, workflows, mappings, message definitions, datasets, scheduled events, task queues, Java and JavaScript actions, connectors, authentications, consumed and published services, database connections and business event services.
What is skipped
  • A document whose new name already exists in its module, in any case.
  • A document whose new name is not valid, e.g. ACT_1Order_Save without its prefix.
  • A document with the same name as an entity, association or module role in its module, or whose new name is one.
  • A document used by a Marketplace module: Marketplace modules are never changed, so their references can't be updated.
  • View entity source documents, document templates and documents of other extensions are never renamed.

The run log lists every skipped document with the reason.

What you need to check yourself
  • Navigation: menu items, home pages and the login page that point to renamed pages, microflows or nanoflows.
  • App settings: the after startup, before shutdown and health check microflows, and the workflow settings.
  • Constant values in App > Settings configurations and in Mendix Portal environments are stored by the constant's name.
  • Java and JavaScript action code, and Java code that uses renamed microflows, constants or enumerations through the generated proxies.
  • Report widgets that use a renamed dataset; scheduled event settings in the Portal; running workflows and queued tasks in deployed environments.
  • Paths to renamed image collections in theme styles, and clients of renamed published services.

The run log lists what applies to your run. Marketplace modules and System are never changed.

If a rename fails or is cancelled

Nothing is changed until the plan is ready. If the run stops before that, the run log lists why.

A document that could not be renamed keeps its name, and references to it are left as they are. If the run stops after documents were renamed, they keep their new names, but references to them may still use the old names. Fix those by hand, or revert through version control.

Known limitations

This tool is built on Mendix's Extensibility API for Studio Pro 11.12. The API is in beta, so behaviour can change between Studio Pro versions.

If errors remain after a successful rename, press F4 to refresh.
